# 실측 STFT 기반 모의 수명 사용법

Pi 바탕화면 `08. 모의 수명 분석`을 실행한다. 기존 DB 원본을 읽어 계산하며 수집기·YOLO를 시작하거나 중단하지 않는다. 완료 뒤 `http://192.168.1.1:8000/lifetime-condition.html`을 새로고침한다. 터미널에서는 `/bin/bash /opt/smart-cylinder-pi5/deploy/run_lifetime_simulation.sh`로 실행한다.

기본 실행은 Pico01~06 각각의 `data/picoNN-analysis.sqlite3`를 읽는 전체 계산이다. DB는 읽기 전용이고 시작 시의 원본 ID 상한을 고정하여 새 수신분이 섞이지 않게 한다. 장시간 읽기 트랜잭션을 잡지 않으며 분석 도중 기존 원본이 삭제되면 재시도를 요구한다. 중앙 인증이나 다른 Pico DB로 자동 대체하지 않는다.

결과는 `data/lifetime-condition-pico01.json`~`pico06.json`에 각각 저장한다. 공용 스냅샷에는 장치별 결과 묶음을 저장하고 웹의 **Pico 선택**에서 해당 장치만 표시한다. 채널 전환 시 입력 사용량·이전 계산 결과는 지운다. 정상 기준이 없는 장치는 보유 데이터와 부족 사유를 표시하며 다른 장치 정상 자료를 가져오지 않는다. 정상만 있는 장치는 정상 STFT를 표시하고 누설 비교 자료가 없음을 건수로 구분한다.

특정 장치만 실행하려면 실행기에 `--cylinder cylinder_03`처럼 전달한다. 기존 중앙 조회 호환은 명시적 `--source supabase`로만 선택한다. 기본은 로컬 Pico별 DB이며 공용 결과가 고정 Pico05로 덮어써지는 구조를 사용하지 않는다.

공개 화면은 `https://ml-cylinder.onrender.com/lifetime-condition.html`이다. 공개 화면은 배포 시점의 분석 스냅샷이다. Pi에서 재분석하면 Pi 웹 자료만 갱신되며 Render 자료는 다시 배포해야 갱신된다. 화면의 자료 생성 시각을 확인한다.

논문 고장 횟수 목록을 수정하여 와이블을 재적합하거나, 직접 설정 모드에서 형상과 척도를 수정한다. 누적 사용량은 실제로 계측한 누적 왕복 횟수만 입력한다. 기본 횟수나 시간/가정주기 환산을 제공하지 않으며 미상이면 잔여수명을 계산하지 않는다. 소리 영향 계수와 외부 수명 기준은 가설이다. 결과와 출처는 JSON으로 내려받을 수 있다. 브라우저 조절은 DB·장비 설정을 바꾸지 않는다.

최초 분석은 Pico05/CYL-005 정상 8세션 2572패킷과 누설 6세션 1772패킷이다. 동일 실물·조건만 비교하며 정상 BASELINE/UNASSIGNED를 기준으로 사용한다. 패킷별 STFT를 계산하고 수신 공백을 음향으로 이어 붙이지 않는다. 확인된 누설 6세션 사이 정지시간만 제외하며 운전 관측 구간은 1011.437089초다. 패킷 수나 수신 간격은 왕복 횟수가 아니다.

수명은 논문 고장 자료의 완전고장 Weibull MLE에 가설 척도 보정 λ(D)=λ₀exp(-γD)를 적용하고 조건부 생존 S(a+r)/S(a)로 평균·중앙 잔여 횟수를 구한다. γ는 실측 고장으로 학습한 계수가 아니다. 최초 자료의 정상·누설 대표 D는 모두 0으로, 이 특징에서는 정상 변동 범위 밖의 대표 차이를 확보하지 못했다. 따라서 같은 사용량에서 대표 수명 차이가 생기지 않는다. 실제 판별 성능이나 교체 시기 검증으로 해석하지 않는다.

원본·라벨·중앙 DB 구조·MQTT 계약은 변경하지 않는다. 분석 JSON은 기존 Pi data 폴더, 웹 요약은 기존 public 폴더에 원자적으로 교체한다. 인증값과 PCM은 공개 요약에 포함하지 않는다.

## 2026-11-04 실측 사용량 및 운영 데이터 변경
이후 사용자 승인으로 측정 영상 주기 2.6016069444초를 동일 속도·정지가 확인된 Pico05/CYL-005의 기존 누설 6세션에 연결했다. 1011.437089초는 약 388.77회의 **구간 추정값**이다. 이전 사용량은 계속 미상이며 자동으로 0을 넣거나 구간 추정값을 생애 누적횟수로 사용하지 않는다. 웹의 영상 모드는 이전 실측 누적횟수를 따로 요구한다. 다른 채널·실물·확인하지 않은 세션에는 이 주기를 자동 적용하지 않는다. 상세 수집 절차는 video_period_collection_guide.md를 따른다.
기본 가정 사용량 50,000회와 시간/가정주기 환산을 화면에서 제거했다. 실측 누적 왕복 횟수 미상은 잔여수명 계산을 차단하며 STFT는 표시한다. 논문 고장횟수는 외부 기준이고 소리 영향은 여전히 가설이다.
분석기의 --operation-since ISO8601 옵션은 해당 시각 이후 라벨 없는 OPERATION 원본을 정상 기준과 비교한다. 같은 채널의 실물·조건 일치는 미확인으로 표시한다. 수집기는 분석과 독립이다. 이번 3분 수집은 원본 0건으로 새 분석 결과를 생성하지 않았다. 기존 스냅샷은 이전 자료다.


## 2026-11-05 기본 분석 대상 변경
기본 실행은 Pico별 SQLite의 저장된 OPERATION 전체를 같은 Pico의 수동 NORMAL 기준과 비교한다. 정상·누설 실험 비교는 명시 옵션 --labeled-experiments로 보존한다. --operation-since ISO8601은 운영 대상의 시작 시각을 제한한다. 운영 자료가 없으면 OPERATION_DATA_REQUIRED이며 누설 자료로 대체하지 않는다. 실물·조건 미확인은 화면에 표시하며 운영 자료를 정상/비정상으로 자동 라벨링하지 않는다. 원본과 MQTT·수집기는 변경하지 않는다. 영상 주기는 기존 확인 6세션 외 운영 자료에 적용하지 않는다.

운영 원본의 Pi 수신 시각이 누락된 경우 원본은 보존하고 분석에서 제외한다. 결과 excluded_packets에 원본ID·세션·PI_RECEIPT_METADATA_MISSING 사유를 기록하고 excluded_packet_count를 화면에 표시한다. 정상 기준과 기존 라벨 실험의 수신시각 검증은 유지한다.


## 2026-11-05 DB 구간 사용량 자동 표시
사용량 기본 모드는 자동 표시다. tools/build_db_usage.py가 Pico별 SQLite를 읽기 전용으로 조회해 data/lifetime-db-usage.json/public/lifetime-db-usage.js를 생성한다. 기존 SQLite 수명 분석 시작 시에도 이 경량 스냅샷을 갱신한다. DB 전체 원본 패킷 수와 정확히 확인된 Pico05/CYL-005 누설 6세션의 수신시각 범위합을 영상 주기로 나눈 구간 추정 횟수를 별도 표시한다. 이 값은 실측 전체 누적량이 아니며 다른 Pico/실물/세션에 주기를 적용하지 않는다. 과거 사용량과 실제 전체 누적량은 NULL이다. 기본 화면은 사용량 입력 없이 구간 추정/미상을 표시하며 잔여수명은 미상 전체 사용량으로 생성하지 않는다. 별도 실측값이 있을 때만 기존 입력 방식을 선택한다. STFT 오류/자료부족과 독립적으로 사용량 패널을 표시한다. Pi 계산은 Pi 스냅샷만 갱신하며 Render는 별도 배포 시점 스냅샷이다.

횟수 단위는 전진+후진=왕복 1회다. 화면의 횟수는 소수점 없이 반올림하여 표시하고 추정값에는 약/구간 추정 표시를 유지한다. 내부 계산과 출처 값의 소수 정밀도는 보존한다.


## 2026-11-05 간헐 시현 비교 진입점
기본08실행기는독립demo_condition_analysis.py --watch를사용한다. 기존정상·누설기준과시현시작이후OPERATION의STFT를비교해누적사용량없이무조건부모의평균수명을표시한다. 논문보고평균167500왕복을수정가능하며실측잔여수명과구분한다. 자세한동작·활동성기준한계·시작종료방법은demo_condition_analysis.md참조. 기존누적사용량을아는경우의잔여계산및--historical --labeled-experiments경로는보존한다.
